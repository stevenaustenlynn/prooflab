# Safe initialization (Phase 6)

`prooflab init [directory]` creates the small public sum starter. With no argument,
the destination is the current directory. A new destination's parent must already
exist. An existing directory may contain unrelated files, which init never traverses
or modifies. Init does not execute code, initialize Git, install software, create an
environment, contact services, alter configuration, or create evidence packages.

The complete write set is exactly:

```text
destination/
  README.md
  comparison-policy.toml
  experiment.toml
  implementations.py
  small.txt
```

No other template directories or files are created. The input is 4, with two trials
per variant. Iterative and formula produce integer answers 10; incorrect produces 9
and exits successfully. The protocol declares `out/result.json` and the built-in
JSON integer measurement `answer`. The separate equality policy assigns PASS or
FAIL. No sum-specific runner, comparison or validation behavior was added.

| Init exit | Meaning |
| --- | --- |
| 0 | All five deterministic files created; `INITIALIZED` and `project_directory` printed. |
| 2 | Invalid invocation, unavailable resources/platform, destination/preflight conflict, or creation/readback failure. Diagnostics go to stderr; mid-write failures describe partial creations. |

There is no exit 5 stub and no force/overwrite option. Repeating init refuses the
conflicts without changing bytes. Before mutation, all resources are read and the
entire write set is preflighted, including the last filename. Existing files,
directories, symlinks (including dangling links), special files, file/directory
prefix conflicts and case-insensitive aliases cannot occupy template destinations.
Files/special files where root ancestors must be directories are rejected.
Destination/root ancestors must be real, unambiguous directories; symlink ancestors
are rejected even if they would lead inside the selected root. Parent traversal in
the supplied destination is rejected rather than normalized across possible links.

The flat resource allowlist reuses the accepted portable-path/alias checks. Each
directory component is opened with no-follow directory handles; file creation uses
`O_EXCL` and `O_NOFOLLOW` relative to the pinned destination handle. An existing
file that appears after preflight is never overwritten. Binding/name checks before
each creation and final byte checks detect ordinary concurrent changes. This needs
OS support for directory descriptors and no-follow opens; unsupported environments
fail closed with exit 2. WSL is the validated environment; no broader platform
claim is made.

A mid-write failure does **not** trigger automatic deletion. Exclusive creation
proves that this invocation created a file, but does not prove nobody has since
edited or replaced it. A check-then-unlink rollback would race with those edits.
Instead the diagnostic lists each created file path in order, whether this
invocation created the destination directory, and that the last file may be
incomplete. No subsequent files are created. Concurrent files/edits are left alone.
If another process moves the root, the pinned directory may be at that moved
location; the diagnostic explicitly calls for inspecting it. Init cannot guarantee
an exact live inventory while another process continues changing that inventory.
Inspect partial files before choosing a fresh destination or manually recovering.
No filesystem-wide transaction, adversarial race isolation, automatic retry,
rollback, or power-loss durability is claimed. Keep directories quiescent.

`importlib.resources.files("prooflab")` loads only the five explicitly named files
under `starter/`. The same explicit package-data entries bundle them in distributions;
package discovery includes only `prooflab`. `src/prooflab/starter/` is authoritative;
`examples/sum/` is a byte-identical public mirror, enforced by unittest. Resource
loading does not depend on cwd or walk to a repository examples directory. No
timestamps, UUIDs, usernames, hostnames, home paths or destination paths are inserted.
Run IDs and timings generated by later execution keep their existing semantics.

See the [generated getting-started instructions](../examples/sum/README.md) and
[repository workflow](../README.md) for actual CLI syntax, returned-path placeholders,
evidence locations, expected scientific FAIL, verification limits and unredacted
artifacts. All five public commands are implemented; no schema changes were needed.
Source-checkout and installed-distribution results are separately reported in the
checkout-only Phase 6 ledger (`docs/phase6-validation.md`); neither establishes
publication. Historical qualification evidence is excluded from distributions.
